# Протокол

Локальный MVP автоматического протоколирования встреч на FastAPI и Vue 3. Загрузите аудио или видео, прослушайте нужное место по метке, уточните имена участников, отредактируйте протокол и отправьте выбранные поручения в YouGile.

## Запуск на Windows

Из корня проекта в PowerShell. Нужны Python 3.11 или 3.12 (64-разрядный) и Node.js 22.12+.

```powershell
python -m venv .venv
# Для NVIDIA с поддержкой CUDA 12.8, например RTX 5060 Ti:
.\.venv\Scripts\python.exe -m pip install torch==2.11.0 torchaudio==2.11.0 --index-url https://download.pytorch.org/whl/cu128
.\.venv\Scripts\python.exe -m pip install -r requirements.txt -r requirements-ml.txt
npm.cmd --prefix frontend ci
npm.cmd --prefix frontend run build
Copy-Item .env.example .env
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8000 --env-file .env
```

Откройте [http://127.0.0.1:8000](http://127.0.0.1:8000). Для первого знакомства нажмите **Открыть пример**. В примере есть синтетическая запись, подготовленная стенограмма и протокол. Для демонстрации достаточно установить зависимости из `requirements.txt`.

Для работы с собственными записями примите условия [Community-1](https://huggingface.co/pyannote/speaker-diarization-community-1) и задайте токен Hugging Face с доступом на чтение в `HF_TOKEN` в локальном `.env`. Если модель уже скачана целиком, укажите её папку через `PYANNOTE_MODEL_PATH`. Приложение скачивает веса Whisper и Community-1 при первом запуске обработки. Чтобы подготовить их заранее, выполните `.\.venv\Scripts\python.exe -m backend.setup_models`. Команда читает переменные процесса, поэтому перед её запуском задайте нужные параметры в PowerShell. После загрузки весов можно задать `HF_HUB_OFFLINE=1` в `.env`.

Диаризация по умолчанию использует CUDA, если PyTorch видит совместимую видеокарту, иначе работает на CPU. Задайте `DIARIZATION_DEVICE=cuda`, чтобы приложение сообщало об ошибке при отсутствии CUDA, или `DIARIZATION_DEVICE=cpu` для запуска на процессоре. На машине без NVIDIA используйте [сборку PyTorch для CPU](https://pytorch.org/get-started/previous-versions/) или пропустите установку CUDA из примера. Whisper выполняет транскрипцию на CPU. Для сравнения с прежней реализацией задайте `DIARIZATION_BACKEND=sherpa` и перезапустите сервис. Перед повторной обработкой используйте те же настройки числа говорящих.

## Как работает обработка

- **Аудио и видео.** Извлечение звуковой дорожки в моно 16 кГц через PyAV. Поддерживаются MP3, WAV, M4A, FLAC, AAC, OGG, OPUS, MP4, WEBM, MOV и MKV. При воспроизведении оригинала набор кодеков зависит от браузера.
- **Говорящие.** pyannote.audio Community-1 выделяет голосовые интервалы локально. Для сопоставления со словами Whisper приложение использует интервалы с одной меткой говорящего в каждый момент времени. Если известно число говорящих, его можно указать при загрузке. В автоматическом режиме группы, на которые приходится меньше двух секунд речи, получают метку «Спикер не определён». Имена задаются вручную в карточке встречи.
- **Протокол.** По русскоязычной стенограмме локальные правила составляют черновик сводки, тем, решений и поручений. Формулировки и сроки можно исправить до отправки. Неявные поручения и относительные сроки требуют проверки человеком.
- **Выгрузка.** Markdown содержит протокол и стенограмму, CSV содержит поручения, JSON сохраняет структурированный результат.

## Очередь и хранение

По умолчанию два отдельных процесса одновременно обрабатывают по одной записи. Остальные записи ждут в SQLite и назначаются в порядке загрузки по мере освобождения процессов. `MEETING_WORKERS` в `.env` задаёт лимит параллельности. Значение `1` подходит для последовательной обработки, в том числе на одной видеокарте с ограниченной памятью. Каждый процесс загружает свои модели в память и использует собственную видеопамять при работе с CUDA. Uvicorn запускайте одним процессом, который управляет очередью и восстанавливает незавершённые записи после перезапуска.

После чтения аудиодорожки в карточке и истории появляется примерное оставшееся время. Сервис уточняет оценку по длительности записи и фактической скорости обработки последних завершённых записей. Пока таких измерений нет, используется начальная оценка по длительности аудио.

Для созвонов с известным составом укажите число людей, которые действительно говорили. Для готовой записи откройте её карточку и нажмите **Повторить обработку**, чтобы применить эти настройки без повторной загрузки. Результат сохраняется отдельной строкой в истории вместе с копией исходного файла, а предыдущий протокол остаётся доступен для сравнения.

В карточке совещания можно раскрыть каждый этап в **Журнале обработки**. Там отображаются события с временем, счётчики фрагментов диаризации, последняя отметка Whisper и итоговые количества реплик, решений и поручений. Журнал обновляется во время работы и сохраняется в SQLite в таблице `processing_events`. При повторной обработке журнал относится к новой попытке. Для записей, завершённых до появления этой функции, событий нет.

Стандартный каталог данных `data/` можно изменить через `MEETING_DATA_DIR`. Лимит одного файла по умолчанию 250 МиБ. Данные и обработка остаются на машине, а при отправке в трекер передаются выбранные поручения.

- **`data/meetings.sqlite3`** хранит карточки совещаний, очередь и историю отправок. В таблице `meetings` поля `speakers`, `segments` и `protocol` содержат JSON с именами говорящих, репликами и таймкодами, протоколом и поручениями. Таблица `task_deliveries` хранит состояние отправки и идентификаторы карточек трекера.
- **`data/media/`** хранит исходные аудио и видео отдельными файлами. База хранит их имена и связывает с карточками совещаний.

Для резервной копии остановите сервис и скопируйте весь каталог данных, чтобы сохранить и базу, и оригиналы записей.

Из истории можно удалить совещание через кнопку с корзиной и модальное подтверждение. Удаляются оригинальный файл, расшифровка, протокол и локальная история отправок этого совещания. Уже созданные карточки в YouGile сохраняются. Если запись обрабатывается, она сразу скрывается из истории, а её обработка останавливается на границе текущего этапа.

## Подключение YouGile

Получите API-ключ и идентификатор нужной колонки по [документации YouGile REST API](https://ru.yougile.com/api-v2). Заполните `YOUGILE_API_KEY` и `YOUGILE_COLUMN_ID` в `.env`, перезапустите сервис. `YOUGILE_ASSIGNEES` позволяет сопоставить имя из протокола с ID пользователя. Если пары нет, имя указывается в описании карточки. Дата переносится в стикер дедлайна.

Проверьте и сохраните протокол, отметьте нужные строки в **Поручениях** и нажмите **В трекер**. YouGile получает стабильный ключ идемпотентности для каждого поручения, сервис сохраняет ID созданной карточки в истории. Для другой системы можно задать `TASK_WEBHOOK_URL` и при необходимости `TASK_WEBHOOK_TOKEN`. Вебхук принимает JSON с полями `event`, `idempotency_key`, `meeting`, `task` и отвечает JSON с `external_id` и необязательным `url`. Обработчик может дедуплицировать запросы по заголовку `Idempotency-Key`.

## Разработка

Для работы с Vue запустите `npm.cmd --prefix frontend run dev` параллельно с FastAPI на порту 8000. Vite проксирует `/api` на бэкенд. При запуске из собранного интерфейса FastAPI отдаёт и API, и статику. Схема API доступна на [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs).

В Git Flow `main` хранит релизы, `dev` объединяет проверенные изменения. Новые функции разрабатываются в `feature/*` от `dev` и вливаются обратно после проверки. Релиз готовится в `release/*` и вливается в `main` и `dev`.
